# Приглашение в МегаСемью. Проверка понимания и измерения

[Открыть учебный макет](prototype.html). В GitHub скачайте файл и откройте локально, чтобы увидеть оформление. В макете две версии сообщений и две роли. Кнопки позволяют переходить между карточками, реальное подключение не выполняется. [Сценарий](scenario.md) описывает упражнения. Действующие условия оператора нужно подтверждать отдельно.

## Аудит обещаний

```sh
python -X utf8 strateg.py audit-copy demo/discovery/audit.json
```

[Результат](results/audit.json) связывает пять формулировок с точными строками макета и спецификации. В исходной версии «любой номер» и «бесплатно» расходятся с учебными условиями, а автоматическое сохранение тарифа не подтверждено. В исправленном варианте организатор сначала проверяет совместимость, получатель понимает, что приглашение ещё не означает подключение. Для публикации команда должна подтвердить фактическую сводку условий и поведение интерфейса.

Агент или ревьюер заполняет `judgment` и обоснование. CLI проверяет, что обещание буквально есть по указанному локатору и что ссылки открываются. Это проверка структуры и происхождения, а не автоматическое чтение изображения или семантическое подтверждение правоты ревьюера. Локаторы остаются внутри пакета.

## Интервью и тест понимания

```sh
python -X utf8 strateg.py interview-guide demo/discovery/interview.json
python -X utf8 strateg.py interview-summary demo/discovery/interview.json demo/discovery/observations_synthetic.json
```

[Гайд](results/interview_guide.md) предлагает три задания: совместимость, оплата и последствия принятия. Сначала участник объясняет экран своими словами и показывает, где увидел ответ. Ревьюер кодирует `pass`, `unclear` или `critical`. Критическая ошибка — например, уверенность, что услуга уже подключена.

[Пример сводки](results/interview_summary.json) полностью синтетический. В v1 вопрос оплаты ещё остался неясным, поэтому следующее исследовательское действие — проверить карточку условий с полями «кто платит» и «сколько» после подтверждения реальных условий. Четыре вымышленных участника и отсутствие рандомизации не измеряют эффект правок. Для своих данных используйте только согласованные обезличенные коды, загружайте одну запись на участника, задание и версию. Команда не собирает записи интервью и контакты.

## События и метрика D7

```sh
python -X utf8 strateg.py audit-events demo/discovery/events_draft.json
python -X utf8 strateg.py audit-events demo/discovery/events_corrected.json
```

[Черновик](results/events_draft.json) находит две проблемы: явное согласие и подтверждение подключения склеены в одно событие, а знаменатель задан по организатору при числителе по приглашённому. [Исправленная карта](results/events_corrected.json) показывает путь «допущен → отправлено → открыто → принято → подключено». Ключ экспериментальной группы — организатор. По приглашению нужен отдельный технический идентификатор, чтобы в QA подтвердить последовательность и связь с организатором. До запуска проверьте дедупликацию и берите первый подтверждённый результат на допущенного организатора в пределах D7. `schema_ready` говорит о согласованности спецификации, а фактическая доставка событий проверяется на тестовой выгрузке.
