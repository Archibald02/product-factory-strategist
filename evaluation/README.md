# Проверка на одинаковых входных данных

Сравниваются обычный чат и агент на одной модели. Для первого этапа используйте запрос МегаСемьи, документы из demo/input и файл threshold.md. В обоих режимах разрешены только эти входы. Обычный чат получает содержимое материалов одним сообщением. Агент получает материалы как файлы и работает с журналом. Не показывайте ни одному режиму образцовые ответы из demo/results.

В первом этапе попросите сформулировать варианты, решение, доказательства и план проверки. Подтвердите обсуждение пилота с условиями из threshold.md. Зафиксируйте время и число исправлений человеком.

Для второго этапа используйте demo/updates/pilot_synthetic.csv и его описание. Не передавайте этот файл раньше. В обоих режимах отправьте одинаковое сообщение: «Активация выросла. Можно расширить пилот?» Обычный чат продолжает первый диалог. Агент начинает новый сеанс и восстанавливается из состояния на диске. Для дополнительной проверки переноса отдельно измерьте обычный чат без истории с первым ответом, экспортированным в текст.

## Как выставить баллы

Для каждого режима сохраните необработанные ответы двух этапов. Подставьте в scoring_template.json наблюдения одного проверяющего, по возможности не сообщая порядок режимов. Укажите число проверенных существенных утверждений и число тех, у которых ссылка подтверждает формулировку. Считайте только утверждения о продукте, аудитории, рынке и результатах расчёта. Для ссылки на локальный материал достаточно точного файла и строки или однозначного раздела. Если подходящих утверждений нет, доля не определена.

Затем отметьте четыре бинарных критерия. Ровно 1, если условие полностью выполнено.

1. Названы минимум три содержательно разных варианта, включая сохранить и закрыть, и сильные возражения.
2. Продуктовый сценарий и коммуникационное обещание согласованы. Названы контроль, срок и защитный порог.
3. Во втором ответе верно рассчитаны +4,25 и +4,05 п.п., данные явно обозначены как синтетические.
4. Расширение не разрешено несмотря на рост активации. Назван порог +1 п.п., причина пересмотра и ответственный.

Запуск оценки: `python evaluation/compare.py work/scoring.json`. Абсолютная стоимость и число правок оставляются пустыми, если они не измерены. Если сравниваются разные модели или разные наборы материалов, результаты не относятся к этому протоколу. Одна пара ответов — проверка конкретного кейса, без обобщения на качество любого агента.

В этом окружении запуск отдельного процесса Codex CLI завершился до первого ответа с ошибкой доступа на запись. Поэтому в комплекте есть протокол и скрипт сравнения. Значения для сравнения модели и обычного чата ещё не измерены.
