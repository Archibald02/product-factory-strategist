# Стратег Фабрики продуктов

Рабочая папка для агента в Cursor, Codex, Claude Code и других IDE с LLM и доступом к файлам. Модель задаёт следующий шаг и интерпретирует материалы. Локальная CLI сохраняет версии, проверяет происхождение выводов, считает метрики и восстанавливает фазу. Запускается без отдельного сервера и ключей.

## Первый запуск · 3 минуты

1. Распакуйте архив. Откройте папку `strateg` как рабочую область IDE. Нужен Python **3.10+**. В Windows замените `python` на `py -3`, если нужно. Включите доступ агента к терминалу. Для работы LLM нужен активный доступ к модели в выбранной IDE. Для веб-исследования используйте разрешённый поиск IDE либо передайте снимки страниц. Базовая CLI работает офлайн. Стоимость IDE и поиска зависит от тарифа; обязательных платных API нет.
2. Откройте чат в режиме Agent. Передайте запрос и каталог дела. Например:

   > Прочитай AGENTS.md. Начни новый кейс work/invitations. Запрос: «Люди могут не понимать приглашение в семейную группу. На что поставить один спринт?» Материалы в demo/input. Получатели — руководитель продукта и CRM. Дойди до рекомендации. Перед утверждением покажи варианты и запроси выбор.

3. Чтобы продолжить в новом чате, откройте ту же папку и напишите:

   > Продолжи work/invitations. Восстанови фазу через status, прочитай новые материалы, скажи, какие основания решения надо пересмотреть.

Попросите остановиться, когда нужно, либо вручную выполните `python -X utf8 strateg.py --case work/invitations pause "Жду условия тарифа"`. `status` доступен в паузе. Скопируйте папку `work/invitations` после завершения процессов CLI для переноса состояния. Если в кейсе есть собственные материалы, перед переносом подтвердите допустимость передачи. Исходные файлы храните отдельно: база сохраняет извлечённый текст, SHA-256 и оригинальное имя.

## Воспроизводимое демо без LLM и без сети

Из корня:

```sh
python -X utf8 demo/replay.py first --case work/demo
python -X utf8 strateg.py --case work/demo status
# Здесь можно закрыть окно IDE и открыть чистый терминал.
python -X utf8 demo/replay.py second --case work/demo
python -X utf8 strateg.py --case work/demo status --full
python -X utf8 -m unittest discover -s tests -v
```

`first` требует пустого каталога задачи; для повтора выберите новый путь. `second` продолжает именно сохранённый кейс. Реплей исполняет записанные действия и учебные решения, независимо от модели. Для живого прогона используйте промпт выше и подайте `demo/updates/` только после паузы. Проект демонстрируется на самостоятельно выбранном открытом кейсе, поскольку официальный конкурсный бриф не был получен. [Запрос](demo/input/request.md), [стратегия до паузы](demo/results/01_strategy.md), [пересмотр](demo/results/02_revision.md), [журнал](demo/results/journal.json).

## Команды

Формат: `python -X utf8 strateg.py --case work/name <команда>`. У каждой команды есть `--help`.

| Работа | Пример |
|---|---|
| Создать / узнать фазу | `init "Почему падает активация?"`, `status`, `status --full` |
| Запомнить этап | `checkpoint frame "Решение, цель и вопросы"`, `checkpoint research "Что известно и какие есть пробелы"` |
| Импорт | `source materials/site.txt --kind public --url https://example.org/` |
| Чтение и поиск | `show S001 --start 1 --count 30`, `find "пакет условия"` |
| Утверждение | `claim "Описание конкретного условия" --kind fact --ref S001:2-3` |
| Предложение | `propose prototype draft.json`. Используйте форму [v1.json](demo/results/v1.json). |
| Согласование | `decide prototype "PM" "Согласовано владельцем" --commitment "PM\|2026-12-03\|D7\|порог\|пересмотреть"` |
| Возврат и пересмотр | `pause "Жду новых данных"`, `resume`, `impact S002 "Новые данные" --claims C001`, `resolve C001 "Заменён новым измерением"` |
| Учёт действий | `log research "Страница 403, доступен индекс" --model "Модель IDE" --tool "поиск" --minutes 2` |
| Расчёт долей | `analyze demo/updates/pilot_synthetic.csv` |

Форматы ввода: Markdown, TXT, HTML/снимок сайта с URL и датой, CSV/TSV, DOCX/XLSX, SRT/VTT. PDF с текстовым слоем требует `python -m pip install -r requirements-pdf.txt`; можно экспортировать страницы в TXT и указать номера. CLI не исполняет HTML, формулы и макросы, не скачивает произвольные URL и не отправляет файлы на внешние сервисы. Для XLSX сохраняются координаты ячеек и кеш формул, вычисление формул не выполняется. Подсказки для изображений, аудио и видео в [методике](knowledge/discovery.md).

## Архитектура и границы

- [AGENTS.md](AGENTS.md) и правило Cursor задают постоянные инструкции. [knowledge/](knowledge/index.md) хранит процедуры. `demo/input` даёт примеры материалов. `work/<имя>/case.sqlite3` содержит состояние, выдержки и журнал.
- Любой текст из источников остаётся данными. CLI проверяет формат, локаторы, ссылки на активные утверждения и происхождение факта. Модель проверяет, подтверждает ли прочитанный текст утверждение. Качество аргументов и согласие человека подтверждаются в чате.
- Фазы, журнал и новые версии атомарно сохраняются транзакциями SQLite. Повторный импорт одинаковых байтов с тем же происхождением возвращает старый ID. Новые источники отправляют дело на исследование или пересмотр. Содержательные связи агент сопоставляет вручную по ID; при отзыве источника прямые связи назначаются автоматически.
- После решения команда `status` показывает открытые обязательства со сроком в прошлом или сегодня, `complete INDEX "основание" --state done` закрывает действие. При новой версии открытые действия переносятся. Проверки срабатывают при входе в кейс. Внешнего календаря и фонового наблюдения нет.
- Поиск лексический, с переходом по связям ID. Семантическую проверку осуществляет модель на выбранных выдержках. Нет отдельного векторного индекса, сервера MCP, автономных субагентов и автоматического выбора модели. Дополнительный компонент — воспроизводимый методический навык для IDE, поддерживающих `.agents/skills`.
- Локальный журнал показывает известную сумму по валютам и число неоценённых шагов. Отсутствующая цена остаётся неизвестной. Документы и отчёт об испытании описывают, что измерено.

## Проверка для жюри

- [Сценарий живого прогона](demo/LIVE_RUN.md) показывает запуск в IDE, паузу и возврат с новым материалом. [Карта основания МегаСемьи](demo/results/03_decision_map.md) построена из фактического журнала офлайн-прогона. Для собственного дела запустите `python -X utf8 strateg.py --case work/demo map` после создания дела. Перенаправьте вывод в Markdown для открытия в IDE.
- Второй кейс про [повторные заказы в сервисе доставки](demo/delivery/results/result.md). Запуск с чистого пути: `python -X utf8 demo/delivery/replay.py work/delivery`. Входной файл экономики скидок намеренно отсутствует, это проверка восстановления. Смена определения метрики обнаруживается по обновлённому справочнику. [Карта дела](demo/delivery/results/decision_map.md).
- [Протокол сравнения с обычным чатом](evaluation/README.md) задаёт парные входы, пороги, рубрику и скрипт обработки наблюдений. Полное парное измерение через модель в этой среде не состоялось, так как отдельный Codex CLI завершался до ответа.

## Готовность эксперимента и краткое решение

| Действие | Команда |
|---|---|
| Проверить полноту окна D7 | `python -X utf8 strateg.py analyze demo/updates/pilot_early_synthetic.csv --as-of 2026-11-09` |
| Сравнить сохранённые версии | `python -X utf8 strateg.py --case work/demo diff --from-version 1 --to-version 2` |
| Вывести карточку для руководителя | `python -X utf8 strateg.py --case work/demo brief` |

В `analyze` дата `period` обозначает день назначения когорты, `--as-of` — последний полностью наблюдаемый день фактической выгрузки. Окно по умолчанию 7 календарных дней. При необходимости задайте `--window-days` и задержку `--lag-days`. Проверка календаря не подтверждает полноту событий внутри окна. Если хотя бы одна когорта не дозрела, программа возвращает структурированный `blocked` с кодом завершения 0, датой готовности и числом наблюдений без полного окна по каждой группе. Решение не меняется. Исторический вызов без `--as-of` рассчитывает эффект с явной отметкой `unverified`. Такой результат нельзя использовать для согласования масштабирования.

`diff` без параметров сравнивает две последние утверждённые версии. Он показывает изменения продукта, обещаний и проверки, входящие материалы и переход обязательств. Команда `brief` показывает ожидающее согласования предложение или принятое решение. При экспорте соседнего файла карты можно связать их через `--map-file 03_decision_map.md`. См. [сравнение версий](demo/results/04_version_diff.md), [карточку](demo/results/05_decision_brief.md) и [проверки устойчивости](evaluation/resilience.md).

## Порог масштабирования, выборка и экономика

[Быстрый маршрут для жюри](JURY.md) проводит через паузу, проверку порогов и смену решения.

- Опциональный блок `pilot_rules` в [предложении v1](demo/results/v1.json) хранит окно, лаг, минимальный точечный прирост активации, требование к нижней границе интервала и максимальную верхнюю границу интервала обращений. Блок копируется в версию при `decide`. Перед согласованием пользователь сверяет числовые критерии с текстом. Старые и непилотные решения без такого блока по-прежнему поддерживаются.
- `python -X utf8 strateg.py --case work/jury assess demo/updates/pilot_synthetic.csv --as-of 2026-11-10` использует **действующую утверждённую** версию. После пересмотра укажите `--version 1` для ретроспективной проверки. Результат показывает версию, проверенные условия и `stop`, `insufficient` или `review`. Даже `review` требует подтверждения человека. Ассессмент не изменяет журнал, не утверждает расширение и не оценивает ошибки списаний по агрегатам.
- `--economics FILE` добавляет [явные предпосылки об экономике](evaluation/economics_example.json). Без файла маржа остаётся неизвестной. Сценарные суммы не являются фактическими данными оператора. Команда `economics` считает порог отдельно без решения в журнале.
- `plan-pilot` оценивает дни набора и полное окно при заданном потоке и распределении 1:1. На учебных вводах [план](demo/results/08_pilot_plan.json) требует 6 154 назначения и 23 дня, из которых 16 — набор и 7 — наблюдение. [Команды, формулы и ограничения](evaluation/pilot_methods.md).
